## モデルピッカーとThinking

入力欄のプロファイル操作と独立したモデル・effortボタンを追加した。
API設定ごとにモデルを表示し、検索できる。通常候補から無効なAPI設定を除外する。
無効・削除済みの現在選択は、色だけでなくテキストと `aria-invalid` でも表示する。

一般設定のモデルセレクターとチャットのピッカーは、同じ `state.currentExecutionSettings` と第1回APIを使う。
モデル選択だけでは成功情報を更新しない。
初期化中は準備中表示にして操作を止める。生成中もモデル・effortを変更できない。
チャット切替と新しい選択を識別し、遅れた能力取得結果が新しい選択を上書きしないようにした。

Thinkingポップオーバーは現在のレベル名、ラベルを下に並べないドット列、右側のリセットで構成した。
モデルの `levels` だけを使い、レベル選択を提供しないモデルではトリガー自体を隠す。
Auto / Offは追加していない。
リセットは `capability.defaultEffort` を `setCurrentChatThinkingEffort()` に渡す。

外側のpointer操作・Escape・Tabで閉じ、必要に応じて起点へフォーカスを戻す。
モデル一覧の矢印キー・Home/End、effortのradio操作とアクセシビリティ名を備える。
ポップオーバーはVisualViewportと画面端に合わせて配置し、スクロール・resizeにも追従する。

## 内部APIとの接続

| UI | 第1回API |
| --- | --- |
| チャット／一般設定のモデル | `getCurrentChatModelRef()` / `setCurrentChatModelRef(ref)` |
| effort表示・選択・リセット | `getModelThinkingCapability()` / `getCurrentChatThinkingEffort()` / `setCurrentChatThinkingEffort(level)` |
| 能力取得 | `refreshModelThinkingCapabilities(apiConfigId)` |
| 思考表示 | `getShowThoughtProcess()` / `setShowThoughtProcess(boolean)` |
| 補助機能・接続・通信 | `saveGlobalSettingsV136(updates)` |
| 個別スイッチ | `getProfileAppearanceSettings()` / `setProfileOverride(kind, enabled)` |
| 色・透明度 | `saveAppearanceValues(kind, updates, {global})` |
| 背景 | `saveBackgroundBlobV136(blobOrNull, {global})` |

`saveBackgroundBlobV136` の第2引数は今回追加した省略可能な引数。
既存呼出しの既定動作を維持し、一般設定からは必ず `{global:true}`、個別編集からは `{global:false}` を渡す。
保存構造は追加していない。

テーマ・背景の共通／個別フォームは同じHTMLを基に作成し、1つのイベント処理で保存スコープを指定する。
現在のプロファイルが個別設定を使っていても、一般設定は共通値を表示・編集する。
オン初回のコピー、オフ時の共通値への復帰、再度オンで以前の個別値の復元を維持した。
背景参照の整理では、引き続き別プロファイル・チャットからの参照を保護する。

`execution-settings-changed` はモデル／能力とテーマ／外観に分けて処理する。
カテゴリのDOMを描画し直さず、編集対象に必要な更新を行う。
入力中の外観フィールドは更新で上書きしない。
成功時の保存通知を追加せず、設定の保存失敗は項目付近に表示する。
API保存はダイアログを閉じ、SD接続テストはセクション内へ結果を表示する。
既存の入力下書き復元の成功通知も除去した。

## 版数とオフライン更新

以下を1.36.0へ統一した。

- `APP_VERSION` / `APP_CACHE_VERSION`
- SWキャッシュ名 `chatai-pwa-cache-v1.36.0`
- HTMLのapp、共通処理、UI、CSS、Dropbox、Function Callingのバージョン指定
- CHANGELOG

SWは同じ版のHTML、CSS、app、共通処理、UI処理などを `cache.addAll()` でまとめて取得する。
失敗したインストールを成功扱いにせず、資源が揃ってから新workerを有効化する。
他の版のキャッシュを横断してapp資源を探さず、現在の版のキャッシュを使う。
旧アプリキャッシュだけを整理し、無関係なキャッシュは保持する。
外部APIとPOSTはアプリシェルキャッシュへ取り込まない。

オフラインで任意の生成SDKを取得できなくても、アプリ全体のDOMをエラー表示に置き換えないようにした。
ローカルの履歴・設定・ピッカーは起動できる。
実API送信や、未キャッシュの外部SDK／JSZipを必要とする機能までオフライン対応したわけではない。
