# v1.36.0 Gemini Thinking 登録修正

## 原因と変更

`settings-v136.js` の完全一致テーブルに `gemini-3.8-flash` が存在せず、
`getModelThinkingCapability()` が unknown / levelsなしを返していた。
チャット側と一般設定側は共通の能力判定でThinking操作を非表示にするため、両方が影響を受けた。

能力定義にモデルごとの対応レベルと既定値を持たせた。未登録モデルの推測は行わず、
`models/` のAPI名前空間を除去した完全一致だけを許可する。
保存構造、UI構造、APIアダプターは変更していない。

## 公式仕様との照合

確認日: 2026-11-06。本アプリのGemini接続先が使用するGenerateContent仕様を優先した。
InteractionsのGemini 2.5向けthinking level変換と混同せず、2.5は従来どおりlevelを送らない。

OpenRouterの既存Googleモデル向け静的フォールバックも同じ定義を参照する。
OpenRouterの取得済みメタデータ優先は維持した。
Live/TTS、Cloud専用モデル、未確認のサフィックスや可変latest別名を類推登録しない。
これはThinking能力の登録修正であり、画像・音声向けの新しい生成機能を追加するものではない。

- [Gemini APIモデル一覧](https://ai.google.dev/gemini-api/docs/models?hl=en): 正式なモデルID。
- [Firebase Thinking仕様](https://firebase.google.com/docs/ai-logic/thinking): 3.8/3.7でminimal指定は400となることを確認。
