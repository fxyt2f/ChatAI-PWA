- `enableApiTimeout`, `apiTimeoutSeconds`

### プロファイル

`getSharedProfileSettings()` は `SettingsV136.profileKeys` の許可リストを使用する。
新規保存、更新、インポート、エクスポート、DB書込に適用する。

- `systemPrompt`, `temperature`, `maxTokens`, `topK`, `topP`
- `dummyUser`, `dummyModel`, `reverseDummyOrder`, `concatDummyModel`, `applyDummyToProofread`, `applyDummyToTranslate`

- `enableMemory`, `memoryAutoSaveInterval`

名前・アイコンは既存のプロファイル直下に保存。
モデル、Thinking、APIキー、補助機能、通信設定、端末設定はプロファイルに保存しない。
新しい2スイッチは、それぞれの値がない場合はオフ。
最初のオンで共通値をコピーし、オフにしても個別値を残す。

### チャットと実行履歴

チャットの `executionSettings`:

```js
{
  schemaVersion: 1,
  modelRef: { apiConfigId, modelName },
  thinkingEffort: 'low', // 対応レベル。不明・レベル指定なし・非対応ではnull
  updatedAt: 0
}
```

未送信設定はタブ別の `sessionStorage['chatai-pwa-execution-draft-v1']` に保存する。
モデル変更ではチャットを新規作成せず、初回送信時のチャット保存で正式な設定に移す。
タブ複製時はブラウザが初期値を複製することがあるが、その後の保存領域は独立している。
タブを閉じた後の永続復元は保証対象外。タブ内の再読込で復元する。

`settings.lastSuccessfulExecution`:

```js
{ schemaVersion: 1, modelRef, thinkingEffort, completedAt }
```

正常な通常応答・再生成だけが更新する。
応答チャットと成功情報は同じIndexedDBトランザクションで書き込む。
複数タブで完了順と保存順が前後しても、より古い完了日時の成功情報では上書きしない。
新規チャット開始時にDBの最新成功情報を読み直す。
参照先が無効な場合は、有効な移行時参照またはAPI候補にフォールバックする。
保存済みチャットの参照が無効なら通常送信を止めて再選択を案内する。

新しい応答の `usageMetadata.tmExecution` はスキーマ2。
Provider、API設定ID・名称、モデル名、適用Thinkingレベル、プロファイルID・名称、開始日時(`generatedAt`)・完了日時を保持する。
Geminiの `modelVersion`、OpenRouter / Z.aiの応答 `model` が取得できる場合は実行モデルとして優先する。
選択モデルと異なる応答なら `requestedModelName` を併記し、適用レベルは推測せずnullにする。
その実モデル名が登録候補にない場合も、次の新規チャットでは参照検証と代替解決を通す。
過去の応答メタデータは更新しない。

各メッセージの `continuation` にAPI継続用データを保存する。
Geminiの署名付きparts、OpenRouterの `reasoning_details`、Z.aiの `reasoning_content`、Bedrockの署名・redacted contentを表示テキストから分離する。
ツール呼出しと応答の順序を `continuation.turns` に残し、保存・再読込後も再送する。
異なるAPI設定・Provider・モデルには署名付き継続データを転送しない。
Geminiの表示可能な思考テキストには「思考要約」の表示名を使う。

### 端末設定

既存の `localUiSettings` を維持し、同期から除外する。
旧プロファイルにしか存在しないローカル設定は、保存済みの端末設定がないキーだけ移行する。

## 移行

1. 旧プロファイルを許可リストで整理する前に読み、既存API／ModelRef移行を実行する。
2. 未登録の旧API資格情報がある場合は、異なる資格情報だけを中央の `apiConfigs` に回収する。
3. 既存の新共通設定を優先する。ないキーはアクティブプロファイル、旧共通設定、既定値の順に採用する。
4. 旧 `themeSettingsProfileScoped` がオンなら、各プロファイルの個別テーマをオンにして旧色設定を保持する。
5. 旧共通背景Blobを `image_store` に移し、共通外観には参照IDを保存する。元Blobもローカルで残し、通常の同期から除く。
6. 旧チャットは選択中の応答メタデータを優先してModelRefを補う。旧Thinkingを新しいeffortへ変換しない。
7. 共通設定・プロファイル・チャット・背景・端末設定・完了マーカーを同一トランザクションで保存する。

完了マーカーは `settingsSchemaVersion = 136`。
失敗・中断では記録せず、再実行できる。
完了後は旧移行によるプロファイルへのModelRef再補完を止める。
旧単独設定からの起動でも、移行前に設定ストアをクリアしない。

他プロファイルの旧共通値は `settingsMigrationBackupV136` にローカル保管する。
資格情報・Blobはバックアップに重複させず、このバックアップを同期やエクスポートにも含めない。
回復インターフェース:

```js
await appLogic.getLegacyProfileSettingsV136(profileId);
await appLogic.restoreLegacyGlobalSettingsV136(profileId); // 秘密情報を除いた旧共通値を明示的に適用
```

初期モデルの互換情報は `legacyInitialModelRefV136` に保存する。

## Thinking対応

| Provider | 実装 |
| --- | --- |
| Gemini | 検証した正確なモデルIDの定義を使用。3 Pro Previewはlow/high、3 Flash Previewはminimal/low/medium/high。3.1系などもモデル別定義。`finalGenerationConfig.thinkingConfig.thinkingLevel` を送信 |
| Gemini 2.5 | 新しいBudgetは送信せず、levelも送らない。思考要約だけ要求してモデルのネイティブ既定動作を使う |
| OpenRouter | `/models` の `reasoning.supported_efforts` / `default_effort` を優先し、取得できなければ検証済みの静的定義を使用。`reasoning.effort` と `exclude:false`。表示オフでもeffortと継続データ取得を維持 |
| Z.ai | GLM-4.6などは `thinking.type:enabled` のみ。検証したGLM-5.2はhigh/max、5.3系はlow/high/maxの `reasoning_effort` を使用。思考本文と通常回答を分離 |
| Bedrock Converse | 検証した旧Claudeは `thinking.type:enabled` と1024トークンの内部budget。4.6の対象モデルはadaptiveと `additionalModelRequestFields.output_config.effort`。方式を混ぜず、非対応モデルには付加しない |

Auto/Off/noneはeffort選択肢に含めない。
モデル名の部分一致でThinking対応を推定しない。
Gemini/Bedrockのモデル一覧から対応effortを得られない部分は静的定義に限定する。
OpenRouterのメタデータ取得には5秒の取得上限を設定し、失敗時は静的定義へ戻す。

## 同期と入出力

既存の同期形式 `version: "2.0"` を維持し、`settingsSchemaVersion:136` と `minimumReaderVersion:136` を追加する。
executionSettings、成功情報、共通補助設定、個別テーマ・背景参照・実体を同期する。
背景は既存の `image_store` / Dropboxアセット転送を共用し、プロファイルJSON内にBlobを重複保存しない。
画像整理では、共通・個別背景、チャット画像、添付アセットの参照を保護する。
背景変更・削除・プロファイル削除後は未参照の背景アセットを整理する。

復元前に未来スキーマと必要アセットの不足を検査する。
復元後は古い同期データにも移行を実行する。
端末設定と現在端末のDropboxトークン、ローカル移行バックアップは保護する。

プロファイル単体JSONは名前・アイコン・プロファイル設定だけを持つ。
個別背景は持ち運び用にBase64アセットを1個添付し、インポート先で新しいアセット参照に変換する。
古い単体JSONのAPIキー・モデル・補助機能設定は現在の共通設定へ適用しない。

API設定の削除・無効化・候補削除では、共通補助参照、現在と保存済みのチャット、このタブの未送信設定を検査する。
別タブのsessionStorageを直接列挙しないため、通常送信・再生成の直前にDBの最新API設定も再取得して検証する。

**旧クライアントによるクラウド上書きは完全には防げない。**
旧クライアントは追加した互換性フィールドを無視しうる。
このクライアント自身は未来データの読込・書込を止めるが、Dropbox全体のサーバー側排他保証を新設したわけではない。

## 第2回UIからの接続

すべて `window.appLogic` 経由。

| 操作 | 関数 |
| --- | --- |
| 現在のモデル取得／変更 | `getCurrentChatModelRef()` / `await setCurrentChatModelRef(ref)` |
| Thinking capability取得／更新 | `getModelThinkingCapability(ref)` / `await refreshModelThinkingCapabilities(apiConfigId)` |
| 現在のeffort取得／変更 | `getCurrentChatThinkingEffort()` / `await setCurrentChatThinkingEffort(level)` |
| 思考表示取得／変更 | `getShowThoughtProcess()` / `await setShowThoughtProcess(boolean)` |
| 個別テーマ・外観の状態 | `getProfileAppearanceSettings()` |
| 個別設定のオン／オフ | `await setProfileOverride('theme' または 'appearance', boolean)` |
| 色・外観の更新 | `await saveAppearanceValues(kind, updates, { global: true または false })` |
| 背景画像更新／削除 | `await saveBackgroundBlobV136(blob または null)` |
| 共通機能設定 | `await saveGlobalSettingsV136(updates)` |

通知は `window` の `execution-settings-changed` イベント。
`event.detail.type` は `chat`, `global`, `theme`, `appearance`, `capabilities`。
状態は `state.currentExecutionSettings`, `state.globalSettingsV136`, `state.lastSuccessfulExecution`。
新規チャット開始は非同期初期化を持つため、必要に応じて `await state.executionSettingsReady` で待つ。
UIで `state.activeProfile.settings` にモデルや補助機能を直接書き込まないこと。
effortなしのcapabilityではセレクターを出さず、Auto/Offを追加しないこと。

## 制約・残る検証と回帰リスク

- 実APIキーを使ったGemini / OpenRouter / Z.ai / Bedrock通信、AWS権限・リージョン別可用性、実Dropbox通信は未検証。
- Gemini 2.5 Flash-Liteは、数値BudgetなしでThinkingを強制する仕様を利用できない。無効なlevelや旧budgetを送らず、ネイティブ既定動作に任せる。
- Budget方式のClaudeは内部budget1024を使い、UIのeffortに数値Budgetを混同しない。Max Tokensが1024以下、またはThinkingと強制tool choiceの組合せは送信を止める。
- 未定義・未知のモデルへ推測でパラメータを送らない。対応モデル追加時は公式メタデータか検証済み定義が必要。
- 旧クライアントのクラウド上書きは防ぎきれない。新形式への移行後に旧版を併用すると、追加フィールドを失う可能性がある。
- 実機のレスポンシブ表示、長い履歴・大きい画像データでの性能、長時間の複数タブ操作は第2回の統合検証対象。
- 署名を壊さないため、継続データにはAPIから返された原文とツール会話を保持する。表示用校正・翻訳テキストとは異なることがあり、履歴サイズも増える。
- 同期・移行は全件読込を行う既存方式を基礎としているため、大規模データのメモリ使用量には注意が必要。
- 別タブが同じ保存済みチャットを同時編集する既存の最終書込優先挙動を、完全な共同編集方式へ変更したわけではない。

第2回では新しい設定画面、モデルピッカー、Thinking操作、2つの外観スイッチを上記APIへ接続し、最終統合検証後に表示とSWキャッシュを1.36.0へ更新する。
